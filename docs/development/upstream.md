# Upstream issues

What Bruno ran into in others' packages, specs and services: where it's tracked, what works
around it here, and what to undo once it's fixed. Check the open ones when touching what they
affect, and at each release. A fixed one moves to the last table until its workaround is gone,
then leaves this page.

| [zerodevapp/sdk#281](https://github.com/zerodevapp/sdk/issues/281) (ours); fix in [zerodevapp/sdk#282](https://github.com/zerodevapp/sdk/pull/282) (ours), not merged | `@zerodev/ecdsa-validator` 5.4.9 requires `tslib` without depending on it; its build's check for that can't fail, since the monorepo installs `tslib`. | Not filed | MetaMask's Smart Accounts Kit, for its EIP-7702 account (`Implementation.Stateless7702`): refuses to name a factory until the EOA is delegated (an EIP-7702 account has none), names its contracts only on chains it lists, and reports its use to MetaMask unless `DO_NOT_TRACK` or `CI` is set. | The user docs' script answers `getFactoryArgs` with nothing, takes Ethereum's contracts, and is run with `DO_NOT_TRACK=1`. | Not filing (2026-10-31): the kit's `getFactoryArgs` throws without factory data, which a Stateless7702 account never has, and viem asks it until the EOA has code, so only a first op that delegates hits it (and, by the code, an undelegated account's `signMessage`). Simplify the script if the kit changes. |
| [denoland/deno#34665](https://github.com/denoland/deno/issues/34665), [our case](https://github.com/denoland/deno/issues/34665#issuecomment-6541558354) (2026-10-31); `deno pack` moving to the jsr CLI in [denoland/deno#37096](https://github.com/denoland/deno/pull/37096) and [jsr-io/cli#6](https://github.com/jsr-io/cli/pull/6), drafts | `deno pack` leaves a workspace member out of the npm `package.json`'s dependencies (`deno publish` declares it on JSR). No package here imports another, so nothing is missing from the client's. | `tools/npm_package.py`, from `make npm-pack`, fails a tarball that imports a package it doesn't declare. | Keep the check. Before moving past Deno 2.9.8: with #37096, `deno pack` downloads the jsr CLI, the newest in a range, when it runs; pin it (`JSR_BIN_PATH`, checksummed, mounted read-only) to keep the pack container sealed, and check the tarball's new layout. |
