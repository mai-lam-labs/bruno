# Sponsored transactions for an EOA, with EIP-7702

For a plain key that holds a token Bruno takes, such as USDC, and no ETH, and is to become a
smart account by EIP-7702. Delegating an account takes a transaction, which takes ETH the key
doesn't have. Here the relay's own transaction carries the key's authorization, so the account
is delegated and its first batch runs in the same bundle, and the account's new code pays for
it in the token.

This is the form of a [sponsorship](index.md) with no transactions of the account's own. The
bundle is two transactions, both the relay's:

1. The first carries the authorization and calls the account, which runs the batch. The batch
   does what you wanted and pays the relay's forwarder.
2. The last calls the forwarder, which sends the payee the payment and reverts unless it was
   paid.

The account is sent no ETH and needs none. The delegate in the script is Uniswap's Calibur, at
the address it has on every chain it's deployed to, and the batch is Calibur's signed batch.
The script is Calibur's throughout: another delegate works the same way, but needs its own
batch and its own signing in place of these. Its comment says which environment variables to
set.

```ts
--8<-- "npm-userops/sponsor-7702.ts"
```

It prints the account, the status, the hashes of the relay's two transactions and what it
paid, in the token's smallest unit.

Three things are worth knowing about how it's put together:

- **The authorization is signed at the account's current nonce.** The relay sends the
  transaction that carries it, so the account's nonce isn't used first, as it would be in a
  transaction of its own. The script reads the nonce from a node, after checking the node is
  the relay's chain's.
- **The batch is signed twice.** The price isn't known until the relay has seen the batch, and
  the batch has to pay the price. So the script quotes with a batch paying one base unit, then
  signs the batch again paying the quoted price. The relay prices such a call as if its
  calldata had no zero bytes, so the price doesn't move when the amount in it changes.
- **`gas` is the quote's.** It's what the account's code is given in the relay's first
  transaction, and the submission states it. It's a
  [measurement, not an estimate](../rest.md#the-gas-of-your-transactions), so for a batch that
  does more than a couple of transfers, state your own.

Only delegate an account to code you trust with it. A delegation hands the account to whatever
code it names.

The account is delegated from then on, so later it can pay for a call from its own batch
without a sponsorship ([REST](../rest.md)), or have ordinary transactions of its own sponsored
[as any account can](index.md).
